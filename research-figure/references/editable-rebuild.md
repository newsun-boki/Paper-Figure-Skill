# Figma / PowerPoint 混合重建

## 共用步骤

1. 打开原始 PNG，检查尺寸、纵横比和细节。复用已认可版本，防止误用后续重设计稿。
2. 记下画布、区域边界、对齐锚点、阅读顺序、连接关系和文字清单，仅保留重建所需信息。
3. 拆成原生结构、原生文本、独立插图，逐项重建。不要把整块含标签和箭头的截图当成插图省略掉信息结构。
4. 背景参考图只用于测量或对照。最终导出隐藏 / 移除它，检查下面没有借原图“补齐”的遗漏。
5. 优先把一个标签做成一个文本对象。仅高保真复刻确有需要时逐词定位，再将整句编组；共享字号和基线，避免独立数字或字母被错误缩小。
6. 复杂插图保留位图即可。无需追求每一条手绘线都可编辑；需要单独修改的科学部件、箭头和标签应分离。

## 局部插图

- 在编辑器中原生裁切原图，可以保留人物、器械、样本、手绘纹理的一致性；生成新资产则使用可用的图像生成 / 编辑工具。
- 不能凭裁切参数已设置就认定成功：检查最终输出中的裁切、长宽比、透明边缘和分辨率。
- 警惕局部图片夹带原文字、边框、箭头，导致双重标签或错位；裁切太紧也可能切掉关键部件。
- 在实际排版尺寸下检查清晰度与背景接缝。只修有问题的素材，避免重新生成整套图。
- 位图独立命名，例如 `illustration/participant`；把“可替换位图”与“可改路径的矢量对象”区分清楚。

## Figma

使用当前环境可用的 Figma 工具，调用前读取相应操作 skill / 文档；不要猜测 API。

- 一个主图对应一个 frame，按 panel / 模块分组，保持字体可用。
- 文本保留文本节点，几何结构保留原生节点或有语义的可编辑路径。
- 每条连接线在正确对象上落点，箭头头部不能悬空、穿过文字或连到错误分组。
- 用户要求在 Figma 里重建时，交付可访问的 Figma 文件；只有本地 SVG 时如实说明尚未完成导入。
- 从最终 frame 导出检查。截图或导出之外，检查节点结构；用独立测试对象验证可选择、移动和编辑后撤销。

## PowerPoint

使用当前环境可用的 presentations skill / 库。画布与论文图比例一致；原生文本、形状和连接线组成结构，每个插图独立成对象。

- 确认字体可用，建立少量有含义的字号层级；先减信息，再扩大必要区域，最后才考虑缩字。
- 图像裁切、字体字距、组变换和连接线在导出后可能与编辑模型不同；打开实际 PPTX 的渲染核对，不只看中间画布。
- 标准标签优先整句编辑。复刻采用逐词文本时，共享基线并编组，避免把字宽误当字号。
- 需要高保真裁切但库输出不正确时，先确认导出的 DrawingML；仅修复证实有问题的部分，再验证引用、裁切方向和最终渲染。不要预设所有版本都有同一个 bug。
- 去重图片资源可以减小文件，但必须正确更新引用并复查图片完整性。
- 验证最终文件可重新读取、对象仍存在、无缺失图片 / 剪裁 / 溢出。实际 PowerPoint 未打开验证时，不冒称已验证原生渲染。

## 高保真对照

同一尺寸导出，禁止把形变后的结果强行缩放到原图尺寸掩盖差异。

```bash
python scripts/compare_renders.py \
  --reference original.png --render exported.png --out-dir build/comparison
```

查看 `side-by-side.png` 和 `overlay.png`，有疑点再看 `difference.png`。渲染字形差异与结构错误分开处理：优先修复缺失、拓扑错误、位置偏差和遮挡，最后调字距、字重与纹理。每次从当前可编辑源重新导出。

同时存在原稿错误和“严格复刻”要求时，将疑点与忠实稿分开呈现，不偷偷修改结论、指标或方法关系。
